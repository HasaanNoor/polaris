# First Research Project

This guide runs a local deterministic Polaris project from a YAML configuration.

## 1. Install

```bash
pip install -e ".[cli,visualization]"
```

Use `.[cli]` if you do not need figure rendering.

## 2. Check Polaris

```bash
polaris system info
```

The command prints version, Python version, optional dependency availability, and the default
project output root. It does not print secrets.

## 3. List Datasets

```bash
polaris datasets list
polaris datasets inspect world_bank_wdi_illustrative
polaris datasets variables world_bank_wdi_illustrative
polaris datasets providers
```

Listing providers reads local metadata only. It does not download source data.

## 4. Select An Example

Example project configurations live under `examples/projects/`:

- `basic_cross_sectional.yaml`
- `governance_health_panel.yaml`
- `education_health_panel.yaml`
- `causal_template.yaml`
- `visualization_example.yaml`

The causal template is illustrative only. It is not a reviewed intervention.

## 5. Validate

```bash
polaris project validate examples/projects/governance_health_panel.yaml
```

Validation parses YAML with safe loading, validates the schema, resolves datasets, checks variables,
checks analysis procedure support, checks AI mode, and verifies output settings. It does not execute
analysis or reasoning.

## 6. Dry Run

```bash
polaris project run examples/projects/governance_health_panel.yaml --dry-run
```

Dry run builds the Phase 13 execution plan and prints planned stages without running statistical
analysis, provider-backed reasoning, or report generation.

## 7. Run

```bash
polaris project run examples/projects/governance_health_panel.yaml
```

The CLI validates the configuration, calls Phase 13 orchestration, prints concise stage progress,
and writes outputs under `outputs/projects/<project_id>/`.

## 8. Inspect

```bash
polaris project inspect <project_id>
polaris project inspect <project_id> --json
polaris project list
```

Inspection reads the stored Phase 13 project artifact. JSON output is clean machine-readable stdout.

## 9. Reports And Visualizations

```bash
polaris report generate <project_id>
polaris visualize list <project_id>
```

Reports are generated by Phase 13 when the project runs. Visualization files appear under the
project `visualizations/` directory when the config explicitly includes visualization
specifications.

## 10. Reproduce

```bash
polaris project reproduce <project_id> --dry-run
polaris project reproduce <project_id>
```

Reproduction uses the stored normalized configuration and verifies that it still resolves to the
same deterministic project ID. It does not silently substitute a different dataset version.

## Exit Codes

- `0`: success
- `1`: unexpected internal failure
- `2`: configuration or validation error
- `3`: research execution failure
- `4`: missing artifact or resource

## Path Rule

Project-relative paths resolve relative to the configuration file. Repository example paths are also
resolved for copied example configs. Paths that escape the Polaris workspace are rejected for data
and manifest inputs.
